# ADR-001: 智能求职多智能体系统形态与协同架构决策记录

## 状态 (Status)
已采纳 (Accepted)

## 背景与上下文 (Context)
构建面向个人（ToC）的 Agentic 智能求职副驾驶系统（FindJob Copilot）需要处理：
1. 涉及高度敏感的用户个人简历、联系方式、职业敏感信息；
2. 跨各大招聘平台（BOSS直聘、前程无忧、猎聘）和社交网络（微信朋友圈、LinkedIn、小红书）的职位抓取与自动化简历投递；
3. 国内各大招聘商业平台具备极为严格的设备指纹检测、IP限制、滑块/短信二次验证等反爬风控机制；
4. 用户日常移动端接收面试邀约通知、每日求职进展的即时触达需求。

对于部署方式，存在两种典型构想：
- 构想 A：纯本地个人运行（Localhost / 桌面应用）
- 构想 B：纯云端微信小程序（SaaS 模式）

## 架构决策 (Decision)
我们决定采用 **“本地安全执行核心 (Localhost Core Engine) + 移动轻量消息通道 (Mobile Notification Channel)” 的端云协同混合架构**，并采用基于事件总线的 **多智能体编排协作模式 (Multi-Agent Orchestration)**。

### 1. 架构职责划分
- **本地核心 (Local Engine)**：
  - 承载所有的隐私数据存储（本地 SQLite 数据库，加密存储 Cookie、Token 与全量简历）；
  - 承载基于 Playwright 的无头/可视浏览器自动化引擎，直接复用本地用户的真实浏览器会话（User Data Profile），在真实本地网络环境下执行低频、高拟人化的投递与简历上传；
  - 承载多智能体任务编排，调用用户指定的 AI 模型（如 DeepSeek、OpenAI、Claude 或本地私有 Ollama 模型）。
- **移动通信端 (Mobile Notification Channel)**：
  - 采用微信公众平台模板消息 / 企业微信 Webhook / Bark / 统一推送服务；
  - 仅传输脱敏后的每日摘要（如：今日精选推荐岗、投递进度卡片、面试日程提醒）；
  - 保留未来在微信小程序上直接查看安全脱敏看板与进行简单指令确认（如批准投递）的扩展接口。

### 2. 多智能体架构选型
- 采用 **Orchestrator-Workers（主调度-专业子智能体）** 架构模式：
  - `JobCollectorAgent`（情报采集）
  - `MatchEngineAgent`（双向智能匹配与量化打分）
  - `ResumeTailorAgent`（针对性自适应简历重构）
  - `AutoApplierAgent`（人机协同自动化投递与上传）
  - `InterviewReviewAgent`（分阶段面试复盘与下一轮备战辅导）
  - `GrowthPlannerAgent`（反馈评估与技能差距行动计划）

## 后果与影响 (Consequences)

### 正向影响 (Positive Consequences)
1. **绝对隐私保障**：用户简历与敏感求职状态绝不上云，完全规避数据合规与隐私泄露法律风险。
2. **免受风控封号**：依托本地原生浏览器和独立家庭网络 IP，避免了云端批量代理抓取带来的封禁风险。
3. **极强的人机协同弹性**：在自动化投递遇到高危人机验证（滑块、短信验证码）时，本地客户端可直接唤醒浏览器弹窗，由用户手动点击完成验证，智能体紧接着继续执行，实现 100% 成功率。
4. **零基础设施成本**：不需要维护昂贵的云端浏览器集群与高防代理 IP 池。

### 潜在挑战与应对措施 (Mitigations)
1. **本地运行要求**：需要用户电脑开机保持后台运行或定时唤醒。
   - *应对*：支持轻量 Docker 容器化与 Windows 计划任务后台静默运行模式；提供一键启动脚本与低资源占用守护进程。
2. **移动端交互有限**：纯通知无法在手机端完整进行复杂简历编辑。
   - *应对*：复杂编辑与简历生成放在电脑大屏进行，手机端仅做轻量查阅、审批与面试日程确认。
